## Summary

The toolbar panel is currently hard-pinned as a **full-width bar across the bottom** of the viewport (`#pi-panel { position: fixed; bottom: 0; left: 0; right: 0; }`). That bottom bar (header + toolbar + context input + Cancel/Submit) **obscures page elements the user needs to click/select** — e.g. buttons sitting near the bottom of the page can't be reached while annotating.

This PR makes the panel **orientation-aware** and adds a one-click dock toggle so the user can move it to any side.

| | Before | After |
|---|---|---|
| Panel dock | Always bottom, full-width | bottom / right / top / left (clickable) |
| Default | bottom | right (so the bottom is clear immediately) |
| Note cards avoid panel | bottom only | any side |

## What's new

A **dock button in the panel header** (next to the close button). Click it to cycle:

```
bottom  →  right  →  top  →  left  →  bottom …
```

The button glyph updates to point at the docked side (▼ ▶ ▲ ◀). The choice is persisted in `localStorage` (`pi-annotate-orientation`) and remembered per-origin.

## How it works

`chrome-extension/content.js`:

- **`#pi-panel` base CSS is now dock-neutral** — only `position: fixed` and visual props remain. Anchors, size, shadow, and border are applied per-orientation via inline styles.
- **`getPanelEdges()`** — returns the viewport edges reserved by the panel for the current orientation, e.g. `{ right: 320 }` when docked right, `{ bottom: 96 }` when docked bottom.
- **`applyOrientation(orient)`** — docks the panel (resets then sets every dock property), updates the button glyph/tooltip, persists the choice, and re-clamps existing notes.
- **`repositionNotesForPanel()`** — re-fits open note cards into the area not occupied by the panel on orientation change.
- **`calculateNotePosition` / `adjustForCollisions` / `handleResize`** — now derive the available area from `getPanelEdges()` instead of a hardcoded `panelHeight`. This means **note cards, clamps, and SVG connectors avoid the panel on ANY side**, not just the bottom. Also added left/top clamping so cards never slip under a top/left-docked panel.
- **`.pi-header` / `.pi-toolbar`** get `flex-wrap: wrap` so they reflow cleanly when the panel is docked to a narrow 320px side column.

`README.md`: documented the dock button in the usage table and added a "Dockable Panel" features bullet.

## Backward compatibility / defaults

- Default orientation is **`right`** so the bottom is clear out of the box. If you'd prefer to keep `bottom` as the default (less surprising for existing users), that's a one-line change in `currentOrientation`'s initializer — happy to switch it.
- No new permissions, no manifest changes, no build step. Existing note-card/connector behavior is preserved for the `bottom` orientation (the math reduces to the original).

## Testing

`node --check chrome-extension/content.js` passes. Manually verified:
- Panel docks correctly to all four sides; shadow/border flip appropriately.
- Button cycles and persists across reloads (same origin).
- Note cards re-clamp when changing dock and never overlap the panel.
- Resize re-clamping works on all sides.

To try it: reload the unpacked extension at `chrome://extensions`, refresh the target page, run `/annotate`.
